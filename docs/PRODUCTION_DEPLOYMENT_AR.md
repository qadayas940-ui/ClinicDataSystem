# نشر عيادة الموصل الخيرية

## البنية المعتمدة

المتصفح أو تطبيق Windows يتصل بخادم HTTPS مركزي، والخادم وحده يتصل بـ PostgreSQL. لا يُكشف منفذ PostgreSQL للإنترنت.

تُثبت نسخة Windows على أجهزة الموظفين مع قيمة `server_url` نفسها. في هذا الوضع لا تشغّل النسخة قاعدة محلية ولا تطبّق ترحيلات؛ إنها عميل للخادم المركزي ومصدر الحقيقة الوحيد PostgreSQL.

هوية كل موظف وصلاحياته وحركاته منفصلة عبر حساب الدخول وسجل التدقيق. لا يجوز إعطاء رابط مختلف لكل تنزيل على الإنترنت، لأن جميع المستخدمين يجب أن يعملوا على التطبيق وقاعدة البيانات المركزيين نفسيهما.

## متطلبات الخادم

- خادم Linux x64 بذاكرة 4GB على الأقل.
- Docker وDocker Compose.
- اسم نطاق وشهادة TLS.
- جدار ناري يسمح فقط بـ 80 و443 وSSH المقيّد.

## التشغيل

1. انسخ `.env.example` إلى ملف أسرار خاص بالخادم ولا ترفعه إلى GitHub.
2. عيّن `SECRET_KEY` و`POSTGRES_PASSWORD` واسم النطاق.
3. شغّل `docker compose -f docker-compose.production.yml up -d --build`.
4. ضع Caddy أو Nginx أمام `127.0.0.1:8000` مع HTTPS.
5. نفّذ اختبار الصحة ثم أنشئ حساب المالك.

## ترحيل SQLite

خذ نسخة غير قابلة للكتابة من `clinic.db`، ثم شغّل `scripts/migrate_sqlite_to_postgres.ps1` من جهاز الإدارة. لا تحذف SQLite قبل مقارنة أعداد المرضى والزيارات والمرفقات وسجل التدقيق.

## ملاحظة صريحة

إعدادات الاستضافة جاهزة، لكن النشر العام لا يُعد مكتملاً قبل توفير خادم واسم نطاق وشهادة TLS ونسخة احتياطية خارجية واختبار قبول فعلي.

## ملخص ملف Excel المرجعي

تم اختبار المستورد على الملف المرفق كاملاً: 4 أوراق و50,146 صف بيانات فعلياً. الأوراق هي مراجعة المرضى (29,308)، المختبر (14,102)، الإحالات (995)، وعيادة العيون (5,741). استخرج النظام 7 أقسام و169 صيغة اسم طبيب و9 منظمين و189 قيمة فحص قبل قرارات توحيد المرادفات. لا تُرفع أسماء المرضى إلى مستودع الشفرة؛ تحفظ داخل قاعدة العيادة فقط عند اعتماد الاستيراد.
